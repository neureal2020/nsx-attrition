# Phase 1 brief: build one program's cumulative roster and list its gaps

You are handling ONE US neurosurgery residency program for an attrition study.
Working dir: `/Users/neureal/Documents/Residency Application Study`.
Goal: every resident who was in the program in academic years 2011-12 through 2026-27, by year and PGY, from the program's own web pages (live + archived), plus an explicit list of the years you could not observe.

## Hard rules
- **Do NOT use WebSearch.** The session's search cap is used up. Do not use other search engines (Google, Bing, DuckDuckGo, Brave) through any route, and do not use a browser. Allowed: WebFetch/curl of the program's own sites, sitemaps, `web.archive.org` via `scripts/wayback.py`, Common Crawl via `scripts/tools/cclocal.py`, NPPES/PubMed APIs.
- Never send the user's email address, name or any other personal identifier to an outside service (e.g. OpenAlex/Crossref `mailto=`, NCBI `email=`, or User-Agent contact fields). Leave those parameters out entirely; if an API rate-limits you, back off and wait.
- Never kill processes by name pattern (`pkill -f ...`, `killall`): other agents run the same scripts on this machine. Kill only PIDs you started yourself (record them with `$!`).
- Never bypass CAPTCHAs or bot checks. Keep Wayback polite: use `scripts/wayback.py` (cached, 2.5 s spacing, backoff). If CDX returns HTML instead of rows, you are being throttled: wait and retry, never treat it as "no captures".
- **Write only these paths:** `data/raw/extraction/p<ID>/` (your scratch; put any custom parser here), `data/intake/rosters_program<ID>.json`, `data/intake/gaps/program<ID>.md`, `data/intake/gaps/program<ID>.json`. Do NOT edit shared scripts (`scripts/*.py`), the docs, or other programs' files. If `roster_extract.py` needs a new layout, copy it into your folder and adapt the copy.
- The only DB writes allowed are through `scripts/21_load_curated_roster.py --program-id <ID> --file data/intake/rosters_program<ID>.json --replace`, plus alumni-page graduation rows inserted into `training_history` (see step 4).
- Do not skip or defer the program because it is awkward (paginated pages, PDFs, JS-loaded lists, odd PGY labels). Work through it. If a year is truly unobservable, say so in the gap file with what you tried.

## Steps
1. **Site history back to 2011.** Start from `programs.website` / `roster_url` in `db/neurosurgery_attrition.db` and the live site. Find EVERY host and path the department used since 2010: old university hosts, division-era hosts under a Dept of Surgery, sponsoring-hospital sites, renamed paths. Use Wayback CDX with `matchType=prefix` on candidate hosts (never append `*` to a prefix query). Follow 301/302s in CDX output (`scripts/tools/gapaudit.py LABEL FROM TO HOST...` lists every URL on the given hosts in a window, with any status). Check live-site sitemaps (`/sitemap.xml`). Record each host/path with its date range.
2. **Roster for every academic year 2011-12 .. 2026-27.** The page can be called anything: residents, current-residents, housestaff, house-staff, trainees, people, our-team, meet-the-residents, education/residency, or a PDF, or a section of a parent page. For each year choose one capture from Aug-Jan (July captures often still show last year; spring can add matched interns). Use `cdx(url, collapse="digest")` to get one row per distinct content version, and CONTENT-DATE each capture (who is PGY-1; compare with neighbouring years) rather than trusting the timestamp. Stale pages exist (Pitt carried a 2003 list into 2011).
   - Parse with `scripts/roster_extract.py` (`lines`, `parse`). **Check the parse by eye, not just the counts.** Known traps: an inline "Name / PGY-n" layout read as headings shifts everyone one PGY; surname-first names; bio text; a singular "Chief resident" subtitle; fellows listed among the PGY-7s (a PGY-7 never seen on earlier rosters is probably a fellow: check the class size against the complement and the graduates list).
   - Firewall block pages (Incapsula, Cloudflare, "Request unsuccessful", "Access denied") are not rosters. Script-loaded (AJAX/JSON) rosters: look for the JSON/API URL in the page source and query it in CDX.
   - The live page is the 2026-27 roster (`source_type: live`, captured 2026-09-27). Fetch it with WebFetch or curl. If it is identical to the 2025-26 roster (PGYs not advanced, no new interns), do NOT load it as 2026-27; list 2026-27 as missing with the reason.
   - A resident first seen above PGY-1 in a year that follows a gap may simply have been hidden by the gap. Classify them as a joiner only if a roster from the year before their first appearance exists and lacks them.
3. **Common Crawl, one pass,** for any year still missing after step 2: `python3 scripts/tools/cclocal.py data/raw/extraction/p<ID>/cc YEAR0 YEAR1 "<SURT prefix>" ...` (SURT drops `www.`, e.g. `edu,duke,neurosurgery)/`). It is slow; run it in the background and keep working. Do not end your turn just to wait for it: when everything else is done, check it with a blocking wait (e.g. `timeout 1200 tail --pid=<pid> -f /dev/null`, or poll with sleep in one Bash call). If it still hasn't finished after about 20 more minutes, kill it and list the unfinished crawls under `problems`. Several agents share this machine's IP: if data.commoncrawl.org returns 403/429/503, back off for several minutes and retry, and list any crawls that still fail in the gap file (`problems`) so phase 2 can retry them.
4. **Alumni / graduates page** (program-side), live and archived: it anchors completions and exposes short classes. Insert each graduate into `training_history`: `resident_name, program_id, institution, role='residency', end_year=<grad year>, completed='yes', source_url, source_type='program_page', retrieved_on='2026-09-27', notes="<program> alumni page graduation year"`. Only for graduation years 2012+ (entrants 2005+), and don't insert duplicates.
5. **Build `data/intake/rosters_program<ID>.json`** in the loader's format (read the docstring in `scripts/21_load_curated_roster.py`): one capture per academic year, `source_url` = the Wayback replay URL `https://web.archive.org/web/<ts>/<original>` (Common Crawl: `"<url> (Common Crawl <crawl-id>, <date>)"` with `source_type: "other"`). Canonicalise name variants to one spelling across years, and keep the listed form in `context`. Only for a year with NO usable capture: add a `source_type: "manual"` entry with rows `reconstructed: true`, and only for people bracketed (listed in the years before AND after) or confirmed by the alumni list. Never reconstruct someone who was not seen later.
6. Load: `python3 scripts/21_load_curated_roster.py --program-id <ID> --file data/intake/rosters_program<ID>.json --replace`. Then `python3 scripts/16_adjudicate_program.py --program-id <ID>` and read the output. Then `python3 scripts/22_export_sources.py --program-id <ID>`.
7. **Check consistency.** Each person should have one entry year (year minus PGY plus 1) across all observations. Check class sizes per entry year against the complement. List everyone who **left the roster before the terminal PGY** (possible attrition or transfer), with the last year and PGY seen, and anyone who **joined above PGY-1** (transfer in). Record the year of each departure and each arrival.
8. **Write the gap report** `data/intake/gaps/program<ID>.md` plus a JSON twin `program<ID>.json` with this shape:
   `{"program_id":..., "name":..., "program_length":6|7, "complement_per_year":n, "first_class_year":yyyy|null, "hosts":[{"url":...,"from":...,"to":...}], "observed_years":[...], "reconstructed_years":[...], "missing_years":[...], "gap_details":{"<ay>":"what was tried / what the captures were"}, "alumni_page":url|null, "departures":[{"name":...,"last_ay":...,"last_pgy":...,"note":...}], "joiners":[{"name":...,"first_ay":...,"first_pgy":...}], "residents_2011plus": n, "adjudication_summary":{...}, "problems":"..."}`.
   A gap is **significant** if some class could have lost or gained someone unseen: any unobserved year, or an observed year whose roster is incomplete.

## If the program is new
If early years come up empty, check when the program was accredited or first matched (history/about pages). Start its timeline at the first class instead of calling earlier years missing, and set `first_class_year`.

## Final reply (short)
Program ID and name, hosts found, observed / reconstructed / missing years, the number of residents entering 2011+, departures and joiners with years, and problems. Keep the reply under 250 words; the details go in the gap file.
